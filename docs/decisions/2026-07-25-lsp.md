# Do not run a language server for F# navigation

> Decided 2026-07-25 · Superseded by nothing · Related: [AGENTS.md](../../AGENTS.md) "Finding F# symbols"

## Decision

Agents navigate F# with `rg` against declaration forms. `fsautocomplete` — the language
server behind Ionide — was integrated, measured, and removed.

## Why it was tried

Text search cannot distinguish F# symbols that share a name. `SessionId` in this repo is a
type, its companion module, a DU case constructor, and twelve record fields;
`rg '\bSessionId\b'` returns 321 hits of which 97 are the type. F# also infers most types,
so a binding's type is frequently absent from the source entirely.

## What was measured

FSAC 0.83.0 (in nixpkgs), driven over MCP, on a 4-core container against this repo
(105 files, ~19k lines, 14 projects):

| | fsautocomplete | ripgrep |
|---|---|---|
| definition (warm) | 1–3ms, exact | ~9ms, 321 hits to read |
| references (warm) | ~80ms, 97 exact | — |
| hover / inferred type | ~2ms | not answerable |
| cold start | ~20s, ~1.3GB resident | none |
| first `references` call | ~12s (workspace-wide check) | none |

Warm queries beat ripgrep on both speed *and* precision. Two findings that cost the most to
establish, recorded so they need not be rediscovered:

- **`.slnx` is not a problem.** FSAC parses `Yession.slnx` and auto-loads all 14 projects
  with no configuration. This was the predicted blocker and it does not exist.
- **The binary alone is not enough.** FSAC loads projects by shelling out to MSBuild. Without
  `dotnet` on PATH it starts cleanly, loads *zero* projects, and answers every query with
  `Couldn't find <file> in LoadedProjects` — a missing toolchain that presents as a corrupt
  workspace. Putting the devenv profile's `bin` on the server's PATH is the whole fix.

## Why it was dropped

The cost is per session, not per repo: ~20s and ~1.3GB every time, in a container that
starts fresh. Break-even is somewhere around a few dozen navigations per session; below
that, `rg` plus the declaration-form discipline in AGENTS.md is cheaper overall. At 19k
lines the precision gap is real but survivable — a 321-hit result is skimmable, and the
compile-order and top-down-scoping properties of F# make declaration-form search reliable.

The MCP bridge was also ~490 lines of transport code to maintain, for which the failure
modes are non-obvious (see the JSON-RPC note below).

## What would change it

- `src/` growing several times over, where 321-hit results stop being skimmable
- a language server with a warm cross-session cache, removing the per-session 20s
- work that is type-driven rather than name-driven, where hover is the only answer

One trap worth carrying forward if it is ever revived: an LSP server's request IDs occupy a
separate namespace from the client's and collide freely, so a JSON-RPC dispatcher must key
responses on the *absence* of `method`, not on `id`. Getting this wrong silently resolves
your pending request with the server's, and reads as "the server returns nothing" —
it cost an entire misdiagnosis (`workspacePeek` appearing to find no projects) during this
evaluation.
