# UX review — basic task walkthrough (2026-08-21)

Method: booted the real manager (`--auth localhost`, scratch data dir,
`YESSION_SANDBOX_NESTED=weak`) and drove headless Chromium over CDP through the basic
flow a new user would take: create a session on the manager page → launch it → open it
→ send a chat message → open a terminal → run a command. Screenshots taken at 1440×900
and true-viewport 390×844 (ui-exploration skill). Findings below, prioritised.

## P0 — broken flow

1. **Created sessions vanish from the manager list.** `POST /sessions` answers with a
   fragment that shows the new row (`stopped` + Launch), but the `/sessions/rows`
   EventSource snapshot that replaces `[data-sessions]` moments later omits
   never-launched sessions entirely — under every filter (`?show=active` included),
   while SSR `GET /` still renders them. The row appears, then disappears in front of
   the user; the session can no longer be launched or archived from the UI at all,
   though it sits in `manager.json`. The rows stream is rendering from a different
   source than the page (live process set vs store). Repro: create a session, wait for
   the stream to connect, watch the row go.

## P1 — high friction on the primary path

2. **Create doesn't launch.** The main flow is create → find the row → Launch → click
   the name link (which only becomes a link once running). Three interactions to start
   working, and #1 currently breaks the middle one. Create should launch and navigate
   (or at least offer to).

3. **The display name never reaches the session.** A session created as
   "design review" opens with header "session" + the raw 26-char ID; the title input
   is empty and the name must be re-typed inside the session. `document.title` is
   "Yession" on every page — tabs are indistinguishable.

4. **Session URLs are ephemeral ports.** Stop + relaunch moved the session from
   :39047 to :37263; the old URL refuses connections — open tabs and bookmarks die
   with no redirect or message, and the manager row is the only way back. (Data and
   title do survive the relaunch — the loss is only the address.)

5. **Identity churns.** Each fresh browser profile/load minted a new animal name —
   five over one walkthrough, three of them visible in a single transcript as
   apparently different people, all actually the same reviewer. There is no visible
   way to see or change your own name. Any cookie loss or second device silently forks
   identity and the roster keeps the stale ones as separate participants.

## P2 — feedback and legibility

6. **First chat message clipped on desktop.** The first message's text is half-cut
   under the header/author row at load (fine at 390px).

7. **Chat empty state is a void.** A new session is a black expanse; no "nobody has
   said anything yet", no pointer to the composer, and the composer itself is an
   unmarked thin bar with a small "→" — no placeholder text. On mobile the affordance
   is near zero.

8. **"+ new" terminal gives no feedback.** The click silently starts the environment
   (`not started` → `running`), and the terminal appeared only noticeably later —
   no spinner or progress between click and terminal.

9. **Every page load logs two 401s** (`/queries`, `/me`) before the handshake
   completes — console noise that would mislead anyone debugging, and a hazard if an
   error surface ever reports fetch failures.

## P3 — polish

10. **Filter chip semantics.** The "active" chip links to `?show=none`; names and
    query values don't correspond (related to #1's split-brain between page and
    stream).
11. **MCP declare form floats detached** below the empty-state line, with its own
    duplicate NAME/ADDRESS/REACHES header row — reads as a second table.
12. **Terminal chrome jargon** — "take", "↑ replay from the start", the "✓ 0" exit
    badge — unexplained, no tooltips.
13. **ProseMirror warns** that `white-space: pre-wrap` is not set on the editor —
    multi-space/newline rendering in the composer is at risk.

## Addendum (2026-08-21, after triage)

- **#1 root-caused**: `ProcessManager.createSession` never calls `publishSessions ()`, so
  the `/sessions/rows` retained snapshot omits sessions created since the last
  launch/exit/rename. Only pages that (re)connect the stream in that window see the
  vanish — the creator's own page swaps from the POST answer and stays correct, which is
  why it doesn't reproduce interactively. Fix plan: `docs/plans/25-manager-session-ux.md`.
- **#10 retracted**: chip hrefs are toggle targets (`SessionQuery.toggling`) — deliberate.
- **#4, #5, #8 skipped** by owner decision; #3 resolved by cutting naming from the manager
  side (naming lives in the session). Plan 25 covers #1, #2, #3, #6, #7, #9 (+#13).

## What held up

Contrast passed everywhere sampled (all ≥ 4.5:1); focus rings are visible and swap
focus-continuity works; icon-only controls carry aria-labels; no horizontal overflow
at 390px; session history and title survive stop/relaunch.
